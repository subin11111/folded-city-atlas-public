# AI 활용내역

연구자는 SLAM과 센서 자료 처리 경험을 바탕으로 수집 조건, 좌표계, 정합 방법과 결과 채택 기준을 정했다. 사진과 3D의 공통 좌표 및 시점 연결도 기존 구현을 사용했다. 웹 디자인과 JavaScript 프론트엔드는 익숙하지 않은 영역이어서 Figma 참조와 원하는 조작 흐름을 제시하고 AI의 도움을 받았다.

아래 입력은 개발 중 전달한 요청을 기능별로 묶고 문장과 표기를 정리했다. 결과에는 AI가 보조한 코드와 연구자가 확인한 내용을 함께 적었다. 모델과 추론 설정은 작업 기록에 대응하는 사례를 기준으로 구분했다. 사전학습 인지 모델과 장면 표현 실험은 [README의 모델 및 알고리즘](../README.md#models)에 따로 정리했다.

## 1 보행 추정 코드와 보정법 비교

### 활용 AI

OpenAI Codex / GPT-6.1-sol Extra high

### 입력 프롬프트

> 수집한 GNSS와 IMU 기록에 GNSS 단독 등속도 칼만 필터와 GNSS·IMU 통합 EKF를 적용할 때의 상태 정의, 관측 구성과 입력 조건을 비교해 줘. 실내에서는 입구에서 초기 위치를 확인하고, 가속도·각속도·중력으로 보행 이동을 추정하는 PDR 기반 EKF와 지도 보조 파티클 필터를 비교하려고 한다. 벽 제약으로 위치 갱신이 정체되는 원인을 방향축, 보폭, 불확실성 전파와 지도 제약 처리로 나눠 분석해 줘. 관련 논문과 오픈소스 구현을 근거로 보정 방법을 비교하고, 같은 센서 입력과 초기화 조건에서 재생·집계할 수 있도록 코드를 구성해 줘. 실시간 필터링과 미래 관측을 사용하는 궤적 스무딩은 구분하고, 갱신 횟수와 벽 통과 여부를 실제 위치 오차와 별도로 보고해 줘.

### 결과

AI는 GNSS 평활화와 보행 이동 추정을 구분하고, PDR 기반 EKF와 지도 제약의 결합을 검토했다. APF_PDR 등 공개 구현을 찾아 지도 보조 PF, 방향·보폭 편향 추정과 궤적 스무딩을 비교하고, 동일 센서 입력의 EKF·PF 재생 및 180개 설정 조합을 집계하는 코드를 작성·수정했다.

연구자는 OSM–SLAM 배치를 유지한 채 구간별 갱신을 대조했다. 2층의 같은 67개 후보에서 EKF 21회, PF 57회 갱신을 확인했다. 실내가 확인된 1층의 0/15회와 2층 시작점 재부여 조건도 함께 기록했다. 이 값은 한 기록의 필터 동작 비교이며 독립 위치 정답에 대한 정확도와 구분한다. 실제 채택 구현은 보행 EKF와 지도 보조 PF다.

## 2 목적지와 계단 이용 조건

### 활용 AI

OpenAI Codex / GPT-6.1-sol High

### 입력 프롬프트

> 연구자가 구축한 층별 보행 격자와 문·계단·승강장 연결을 입력으로, 선택한 A* 알고리즘의 경로 탐색 코드를 구성해 줘. 학생취업처, 고전음악감상실, 학생식당과 CU의 출입 지점을 목적지로 등록하고, 대각선 이동의 장애물 모서리 통과와 등록되지 않은 층간 이동을 차단해 줘. 이동 비용은 미터 단위의 경로 길이로 계산하고, 메인 계단·서브계단·엘리베이터 이용 조건을 분리해 대안을 반환해 줘. 특히 고전음악감상실은 오른쪽 서브계단을 포함한 경로와 메인 계단 경로를 비교해 줘. 같은 그래프의 Dijkstra 결과로 최단거리 계산을 점검하고, 승강기 대안의 기하 거리와 대기·운행 시간은 구분해 줘. 반환 경로는 연구자가 구현한 사진·3D 공통 좌표를 유지하면서 웹 화면에 표시해 줘.

### 결과

AI는 층별 보행 격자의 A* 탐색, 문·계단·승강장 연결과 정책별 경로 반환 코드를 구현·수정했다. 장애물 우회와 대각선 모서리 차단, 기존 사진·3D 좌표 연동을 사용하는 경로 표시 코드도 보조했다.

연구자는 실제 사진으로 문과 계단 접근점을 확인하고, 경로 회귀검사 13개와 같은 그래프의 Dijkstra 거리 대조로 계산을 확인했다. 고전음악감상실의 서브계단 경로는 메인 계단보다 모델상 6.1 m 짧았다. 이후 보건실 접근점도 같은 그래프에 연결했다.

## 4 기존 사진과 3D 시점 연결의 화면화

### 활용 AI

OpenAI Codex / GPT-6.1-sol High

### 입력 프롬프트

> 연구자가 구현해 둔 지도·사진의 좌표와 시점 연결을 그대로 사용해 줘. 건물을 선택하면 출입구 앞을 보여 주고, 이후에는 로드뷰처럼 촬영 사진을 보며 왼쪽·오른쪽 방향을 선택할 수 있게 해 줘. 사진을 보는 지점에서 3D 보기를 누르면 같은 위치와 방향의 3D 화면으로 전환되도록 기존 연동 기능을 웹의 버튼과 화면 상태에 연결해 줘.

### 결과

AI는 기존 위치·방향·층 메타데이터를 이용하는 사진 패널, 방향 선택 버튼과 3D 전환 조작부의 프론트엔드 코드를 보조했다. 공통 좌표와 사진·3D 시점 연결은 연구자가 이미 구현한 기반이다. 연구자는 PRIME HALL 앞의 같은 지점에서 사진과 3D를 오가며 위치와 방향이 유지되는지 확인했다.

## 5 모바일 목록과 지도 조작

### 활용 AI

OpenAI Codex / GPT-6.1-sol High

### 입력 프롬프트

> 모바일에서 글자와 버튼이 크고 화면이 복잡해 보여. 기능은 유지하되 장소 둘러보기와 길찾기를 한 흐름으로 정리해 줘. 아래 목록을 위로 끌어올리면 스크롤하기 편하게 펼쳐지고, 내리면 지도를 넓게 볼 수 있게 해 줘. 별도의 넓게 보기 버튼 대신 드래그 방식을 사용하고 아이폰 Safari에서 위아래가 잘리거나 어색한 공백이 생기는 화면도 함께 조정해 줘.

### 결과

AI는 하단 패널의 드래그·접힘 상태를 다루는 `sheet-controller.js`, 모바일 배치와 `visualViewport` 및 safe-area에 맞춘 영역 조정 코드를 작성·수정했다. 연구자는 휴대폰 화면과 캡처를 전달하며 지도 면적, 글자 크기와 패널 높이를 반복 조정했다.

## 6 현재 위치와 헤딩의 지도 표시

### 활용 AI

OpenAI Codex / GPT-6.1-sol Extra high

### 입력 프롬프트

> 휴대폰에서 받은 현재 위치와 헤딩을 지도에 표시하고, 일반 지도 앱처럼 안내를 이어갈 수 있게 해 줘. 위치와 방향 입력을 웹 화면에 연결하고, GNSS 재현 화면도 캡처해 구현 결과를 보여 줘. README는 업데이트 내용을 계속 덧붙이기보다 전체 흐름에 맞춰 정리해 줘.

## 7 운영 화면 정리와 배포

### 활용 AI

OpenAI Codex / GPT-6.1-sol High

### 입력 프롬프트

> 일반 사용 화면에 연구·데모용 설명과 버튼이 많이 보여. 이런 기능은 메뉴 안쪽에 모으고 기본 화면은 검색과 길찾기에 집중하도록 정리해 줘. 연결된 GitHub 저장소를 기준으로 Vercel 자동 배포를 준비하고, 수정한 웹을 커밋·푸시해 배포할 수 있게 구성해 줘.

### 결과

AI는 사용자용 화면과 연구 도구를 분리하는 메뉴 코드, 웹 빌드 및 Vercel 정적 파일·API 연결 설정을 보조했다. 연구자는 기본 화면의 기능과 배포 주소를 확인하고 반영 여부를 결정했다. 현재 운영 빌드는 사용자용 화면에 실험·재생 도구를 노출하지 않도록 구성했다.
