# 카메라 없는 실내 안내와 배포 화면 분리

## 바뀐 동작

기존 웹은 실외 Geolocation 위치를 따라가다가 입구 확인 버튼에서 위치 수신을 종료했다. 그 뒤에는 입구 기준 경로와 사진 탐색만 제공했다. 보행 추정에서는 시작 위치를 확인하고 실제 DeviceMotionEvent 및 기준 방향에 대한 휴대폰 회전을 받아 이동을 계산한다.

실외는 기존 위치 기반 칼만 필터를 유지한다. 실내는 선택한 장소를 기준으로 시작하며 GNSS를 보행 위치에 다시 주입하지 않는다. 실내 GNSS의 수십 m 편향이 실내 추정점을 이동시키는 것을 막기 위한 분리다. 휴대폰 브라우저의 센서 자료는 고속 원시 GNSS/IMU 스트림과 다르며, INS 기반 GNSS/IMU 긴밀 결합을 구현한 것으로 부르지 않는다.

## 보행 처리

`web/public/walking-sensors.js`가 센서 시각과 휴대폰 축을 처리하고 걸음을 검출한다. `map-particle-filter.js`가 위치 분포를 갱신하며 `indoor-position.js`의 보행 격자와 경로 진행 계산을 함께 사용한다. 가속도 크기를 50Hz로 시간 재표본화하고 0.65Hz 고역통과 및 3Hz 저역통과 Butterworth 필터에 넣는다. 실제로 받은 두 표본 사이만 보간하며 250ms 이상 끊기면 필터를 재시작한다. 초기 1초, 0.32초 최소 주기와 양·음 피크를 모두 거친 주기로 약한 흔들림을 거른다. Weinberg 형태의 보폭식에 0.48–0.85m 범위를 둔다. 기본 계수 0.55는 개인 보폭을 실측해 식별한 값이 아니다.

Safari의 alpha, beta, gamma는 초기 자세에 대한 상대 좌표일 수 있다. 이를 곧바로 북쪽 기준으로 해석하지 않는다. 입구에서는 사용자가 건물 안쪽을 향한 채 약 1초 멈춰 시작 방향을 맞춘다. 그 뒤에는 ZXY 회전행렬에서 얻은 수평 전방의 변화를 추적한다. 화면을 세운 자세는 후면 카메라 방향, 평평한 자세는 화면 위쪽 방향을 사용한다. 다른 장소에서 시작하거나 화면을 다시 연 경우 잠깐 평평하게 들어 유효한 나침반 기준을 얻는다. 방향의 기준에는 목적지나 추천 경로를 넣지 않는다.

`gravity-heading.js`는 회전율을 중력 방향에 투영해 수평 회전량을 적분한다. 중력을 분리한 가속도가 함께 있으면 두 가속도 스트림의 차로 중력 축을 구하고, 없으면 중력 포함 가속도의 저역통과를 사용한다. 회전율이 없으면 상대 자세 전방으로 대체하며 250ms 이상 끊긴 구간은 적분하지 않는다. 방향을 돌리기만 해서는 위치가 이동하지 않는다.

입자는 평면 위치, yaw, 방향 드리프트와 보폭 배율을 가진다. 한 걸음의 방향 및 길이 후보를 표본화하고 벽 통과 후보를 제거한 뒤 systematic resampling을 적용한다. 배포 설정은 초기 1,536개, 범위 768–2,048개다. 표시점은 벽 안에 놓일 수 있는 입자 평균 대신 평균에 가까운 실제 입자로 선택하며, 직전 표시점과 벽을 가로지르는 전환도 거부한다. 분산은 모델 내부 값이며 현장 측량으로 구한 정확도 범위가 아니다. 기존 보행 EKF는 비교 기준으로 보관한다.

개인 보폭은 이용 안내 안의 ‘보폭 맞추기’에서 설정한다. 줄자 등으로 별도로 잰 5–30m 직선 구간과 감지한 8걸음 이상의 진폭을 사용한다. 경로 API의 길이나 목적지까지 남은 거리를 보폭의 정답으로 쓰지 않는다. 측정 중에는 위치 안내를 멈추며, 끝나면 실제로 이동한 현재 위치를 다시 선택한다. 보폭 계수와 측정 거리·보수만 기기에 저장하고 센서 원본을 서버에 보내지 않는다.

보행 격자와 명시적으로 등록한 출입문 통로를 이동 제약으로 사용한다. 한 걸음의 선분 전체가 통과 가능한지 확인하며 대각선 벽 모서리 통과와 벽 너머 스냅을 거부한다. 계획 경로는 보행 이동의 입력이 아니다. 센서가 없거나 오래되면 표시점을 유지하며 안내를 대기 상태로 바꾼다. 화면이 가려지면 샘플을 적분하지 않고, 다시 열린 뒤 누락 걸음을 만들어 채우지 않는다.

층은 자동으로 맞춘 값이 아니다. 해당 경로의 계단·엘리베이터 시작 지점에 접근하면 이동을 잠시 멈추고 사용자가 도착한 층을 확인한 뒤 다른 승강장 기준점에서 이어간다. 위치가 어긋나면 사진과 장소 이름으로 다시 기준점을 선택할 수 있다. 경로를 다시 찾을 때는 현재 층과 추정 XY를 같은 A*에 전달한다.

## 배포 범위

`web/scripts/build-product.mjs`가 `web/public`에서 제품 파일만 `web/dist`에 만든다. Vercel은 dist를 게시한다. 연구 소개, GNSS 재현, 사진 검사와 원 GNSS JSON은 게시하지 않는다. 연구 자료와 이전 분석은 저장소에 보관한다. 화면에서 실외 안내, 실내 보행 안내, 사진 미리보기를 구분한다.

## 확인 범위

단위 시험은 정지와 미세 흔들림, 걸음 주기, 방향 미수신, 벽 통과 차단, 층 중첩, iOS 두 권한 요청의 사용자 동작 시점, 권한 거부를 다룬다. HTTP 시험은 현재 층 좌표의 재경로 계산 및 잘못된 입력 거부를 다룬다. 로컬 제품 서버에서 연구 페이지의 404와 실제 안내 진입을 확인한다.

10월 20일 Sensor Logger 실측의 [입력 빈도와 방향축 대조](2026-10-21-walking-sensor-calibration.md)에 이어 [지도 보조 PF 180개 조합](2026-10-21-map-particle-pdr.md)을 계산했다. 배포 기본 조건에서 2층 위치 갱신은 같은 67회 중 EKF 21회, PF 57회였다. 1층은 PF도 30회 중 9회만 갱신했다. 2층 승강장 재초기화를 가정한 네이티브 기록 재생이며 Safari 현장 측위 오차를 측정한 시험은 아니다. 출입문·층 확인과 위치 수정 UI는 누적 오차를 사용 흐름에서 다룬다.

API 기준은 [W3C Device Orientation and Motion](https://w3c.github.io/deviceorientation/)과 [MDN DeviceOrientationEvent](https://developer.mozilla.org/en-US/docs/Web/API/DeviceOrientationEvent)를 참고했다. iOS 권한은 네트워크 대기 전에 두 요청을 같은 클릭 처리 구간에서 시작한다.
