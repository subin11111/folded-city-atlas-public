# 보고서 비평에 따른 비교 기준 재정리

2026-10-21. 기존 자료를 재집계한 분석이며 새 측량이나 사용자 시험은 포함하지 않는다. 운영 지도의 지리 배치, 표시 높이와 방문자 위치 필터는 변경하지 않았다.

## 1. 반영 범위

제출 제목과 수집 중 SLAM의 단계별 설명은 유지한다. 카메라-IMU VIO, RGB-D 특징·재방문 검색과 기하 검사, 저장 포즈 그래프, 관측 후처리의 역할을 나눈다. 기존 알고리즘을 현장에 적용한 것과 알고리즘 자체를 발명한 것을 혼동하지 않는다.

| 비평 | 반영한 것 | 남은 평가 |
| --- | --- | --- |
| 나빠진 중간 후보를 BA 기준선으로 사용 | 기존 미리보기 대비 거리와 겹침을 앞에 표시 | 별도 관측·구역에서 BA 일반화 |
| 전체 지도 품질 표본 부족 | 세 구역의 동일 대응 90개 집계, 개선·악화 모두 기록 | 두 연결 촬영본의 표면 표본과 독립 측량 |
| 후보 선택의 사후성 | 항목 수, 고유 궤적 수 및 사후 선택임을 기재 | 사전 채택 기준과 별도 평가 집합 |
| GNSS 편향과 변동 혼합 | 평균 차이 벡터와 평균 제거 잔차 분리 | 독립적인 지도 지리 기준 |
| 배포 필터와 평가 입력 차이 | 배포 모듈 직접 호출, 반경 해석 두 가지 재생 | Safari 현장 센서 시험 |
| ML 결과가 AI 고지에 섞임 | LoFTR·YOLO·Gaussian 제한 실험을 본문으로 이동 | 같은 조건·후보의 모델 비교 |
| 사용자 가치 검증 부족 | 시제품 시연과 효과 평가 구분 | 초행자 성공률·이동시간 시험 |

보건실과 도서관은 연구 동기이며 이번 목적지 시험의 대상은 아니다. 수집 범위는 제1학생회관의 실외 접근, 로비, 두 계단과 2층 복도 일부다.

## 2. 동일 표면 대응의 집계

입력은 `docs/assets/session-portfolios/*/summary.json`이다. O00, P00과 구역별 선택 후보에서 `(a, b, kind, 같은 쌍·종류 안의 순번)`이 일치하는 관측만 비교한다. 세 방법의 키 집합이 다르면 집계를 중단한다. 값은 저장된 `patches[].value_m`이다. 벽과 수평면의 거리 잔차이며 위치 정답과의 오차가 아니다.

| 구역 | 후보 항목 | 고유 궤적 해시 | 대응 수 | 개선 / 악화 |
| --- | ---: | ---: | ---: | ---: |
| outside | 17 | 15 | 16 | 15 / 1 |
| lobby | 18 | 16 | 36 | 22 / 14 |
| floor2 | 21 | 19 | 38 | 22 / 16 |
| bridge_out1f | 17 | 12 | 0 | — |
| bridge_12_sub | 18 | 16 | 0 | — |

전체 90개의 중앙값/P90은 5.7279/32.3704 cm에서 5.1975/15.6254 cm로 변했다. 31개는 악화했고 로비 중앙값도 증가했다. 벽과 수평면을 합친 집계 외에 그림에는 종류별 누적 분포를 표시한다.

![표면 잔차 분포](../assets/critical-review-20261021/surface-distribution.png)

O00은 앱 저장 최적화 자세다. P00은 같은 자세의 깊이 전처리 비교로, 이 고정 표면 지표는 동일하다. 이 집계는 원시 센서를 연속 입력해 다시 계산한 RAW/PGO/BA ablation이 아니다. 대응을 개발 과정에서 반복 사용했고 일부 프레임·표면이 서로 연관돼 있어 독립 표본의 신뢰구간을 계산하지 않았다. 고정 임계값에 대한 별도 자료의 민감도·오수락률 시험도 수행하지 않았다.

선택 후보는 실외 J01, 로비 N05, 실외 연결 H03, 2층 J04와 서브계단 H03이다. 잔차와 전체 형상을 함께 본 사후 판단이며 단일 가중 종합점수의 최적해로 제시하지 않는다.

## 3. BA의 공정한 기준선

| 같은 벽의 지표 | 기존 미리보기 | BA 반영 F01 |
| --- | ---: | ---: |
| 관측면 사이 거리 | 4.048 cm | 5.141 cm |
| 20 cm 내 양방향 최소 겹침 | 59.04% | 51.93% |

중간 악화 후보의 115.793 cm에서 감소한 것은 복구다. 기존 미리보기보다 좋아진 결과는 아니다. 재투영과 깊이 잔차 P90도 BA 피팅에 사용한 관측의 내부 잔차다. 최종 J04는 이 BA 후보가 아니며, 지속 track이 없는 548↔981의 개선을 BA 효과로 설명하지 않는다.

## 4. GNSS와 지도 차이의 분해

같은 시각의 차이를 `e = GNSS - 지도 위치`로 두고 다음을 계산한다.

```text
RMSE² = |mean(e)|² + mean(|e - mean(e)|²)
```

원본 지도 기준은 DB 저장 자세, 세션 배치와 사진 위치 보간으로 재현한 웹 지도 위치다. 독립 측량이나 원래 선택 포즈 CSV의 대체 정답이 아니다. 평균 제거는 전체 기록을 이용하는 진단이며 배포 필터에 주입하지 않았다.

| 구간 | 공통 시각 | 평균 벡터 크기 | 평균 제거 후 RMS |
| --- | ---: | ---: | ---: |
| 실외 | 337 | 3.4230 m | 3.2643 m |
| 로비 | 293 | 15.7559 m | 10.4190 m |
| 메인 계단·2층 | 332 | 12.4947 m | 23.9423 m |

고정 ENU 오프셋 `[2,-2] m`을 제거하면 지도 XY 차이 벡터는 일정량만 이동한다. 전체 대응을 사용한 수치 검사에서 평균 제거 잔차의 차이는 최대 `2.13e-14 m`였으며 대수적 불변성의 구현 검사다. 정확도 성과가 아니다. 이 검사 파일은 필터 공통 집합과 달리 반경 초과 관측까지 포함하므로 로비 평균과 잔차는 위 표와 다르다.

![편향과 실외 비교](../assets/critical-review-20261021/gnss-bias-outdoor.png)

실외 동일 337시각의 상대 RMSE는 원 수신 4.7300 m, 칼만 4.8752 m와 RTS 4.6603 m였다. 칼만의 위치 정확도 개선 주장은 성립하지 않는다. 지도 대비 속도 증분 차이 RMS는 334개 간격에서 0.8464/0.6287/0.4469 m/s였지만 이것도 독립 속도 정답과의 비교가 아니다.

### 배포 코드와 입력 규칙

`web/scripts/review-gnss-settings.mjs`는 실제 `web/public/gnss-filter.js`를 가져온다. 모듈과 입력의 SHA-256을 출력에 남긴다.

- `unspecified_radius`: iOS 원본 반경을 `sigma=r`로 둔 기존 입력 규칙.
- `browser_95_assumption`: 같은 iOS 반경을 웹 95% 반경이라고 가정한 민감도 시험. `sigma=max(1.5,a/2.4477)`.

두 번째를 Safari 실측 시험이라고 부르지 않는다. 각 규칙 안에서 raw/Kalman/RTS는 같은 history 시각 집합으로 비교하며 관측 갱신이 거부된 시각에는 예측 상태도 포함한다. 두 규칙의 수락 수는 별도 기록한다.

## 5. 표시와 경로의 사람 개입

보기용 표면의 두 수동 지정 벽 영역에서 잡음 12,170면을 제거하고 사진 지지 벽 5,100면을 더한 처리는 카메라 자세 보정과 다르다. 보행 연결 5개와 목적지 5곳도 등록·검토했다. 이 보완을 자동 SLAM 복원 성과로 집계하지 않는다.

계단 도보 거리와 승강기 수직 연결 길이는 다른 비용이다. 승강기 대기·운행 시간이 없으므로 36.4 m의 승강기 기하 경로를 최단 도보나 최소시간으로 순위화하지 않는다. 1층의 식당과 CU는 불필요한 층 이동 여부의 대조 항목이다.

## 6. 제한 실험과 생성형 AI 고지

LoFTR 200회 중 국소 통과 1쌍은 동일 후보군의 SIFT 통과율과 직접 비교한 값이 아니다. Gaussian은 중심과 카메라 고정, densification·SH 없이 600 step의 표시 실험이다. 따라서 일반적인 3DGS의 성능을 결론 내리지 않는다. 낮은 PSNR의 원인은 입력·투영·렌더링과 학습 조건을 함께 점검할 과제다.

이 결과는 보고서 본문에 두었다. 생성형 AI 활용내역에는 연구자의 방법 지정, 코드·문서 보조와 실제 확인 범위만 남겼다. 실제 사진과 계산 그림에 `AI 그림`이라는 캡션을 쓰지 않는다.

## 7. 재집계

저장소 루트에서 실행한다. Python에는 NumPy와 Matplotlib, 한글 글꼴이 필요하다. GNSS 재생에는 프로젝트의 Node ESM 환경을 사용한다.

```sh
node web/scripts/review-gnss-settings.mjs
python scripts/review_existing_evidence.py
# Ubuntu 글꼴 예시
python scripts/review_existing_evidence.py --font-family NanumGothic
```
